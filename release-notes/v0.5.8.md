## MDLite 0.5.8 — calmer OpenAPI Preview while editing

A lightweight native editor (Qt 6 + Scintilla) with built-in Preview and Terminal. This follow-up to 0.5.7 makes OpenAPI (Swagger UI) Preview cheaper and steadier while a spec is being edited.

### Changes since 0.5.7
- **Swagger UI is rebuilt once per editing pause.** Before, every pause in typing (over 200 ms) re-sanitized the whole spec and built a new Swagger UI instance. Now an edit to the spec already shown waits 600 ms, so a burst of typing is rendered once.
  - Measured in the WebView2 host with 10 edits of a 99 KB spec, 250 ms apart: Swagger UI builds dropped 10 → 1. Five seconds after the burst, the Preview's JavaScript heap was 24 MiB instead of 62–75 MiB, and the WebView2 processes used 137 MiB instead of 218–225 MiB.
  - Opening a spec, switching files and changing format are still immediate. Opening a spec uses the same memory as before.
- **No blank flash while editing a spec.** The shown documentation stays on screen until the new version has rendered, then it is replaced in one step.
- License: GPL-3.0-or-later, with the third-party licence set included in the package.

### Requirements
- Windows 10/11 x64. Preview and Terminal use the Microsoft Edge **WebView2 Runtime** (preinstalled on Windows 11).

### Install
- **Installer:** run `MDLite-0.5.8-windows-x64-setup.exe`. The app is not code-signed yet, so Windows SmartScreen may ask you to confirm ("More info" → "Run anyway").
- **Portable:** unzip `MDLite-0.5.8-windows-x64.zip` anywhere and run `Workspace.exe`.

Settings are stored in your user profile (AppData) and are kept when you uninstall or update.

### Validation and known limits
- Built with Qt 6.8.3 / MSVC 2022 on Windows 11. 37/37 automated tests passed, including a new edit-churn gate in the real WebView2 host. Deployment smoke tests passed for the package and for an installer install, and the silent uninstall removed the files and the Start menu shortcut.
- The changes in this release were not independently reviewed.
- Not yet validated: Windows 10, clean-machine installs, Linux/macOS (no Preview/Terminal host there yet), live screen-reader sessions.
- With Preview open on a large image, memory still peaks briefly inside WebView2 while it receives the image (≈215 MiB for a 14 MiB image).
- Editor-only memory is about 15 MiB at 1600×1000 px with no file open (more on large or high-DPI windows); the 30 MB target holds only for small windows.

Details: `docs/footprint-0.5.6.md` in the source archive. Third-party notices are included in the package (`licenses/`, `terminal/THIRD_PARTY_NOTICES.md`).
