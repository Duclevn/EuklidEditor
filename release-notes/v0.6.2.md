## MDLite 0.6.2 — Faster Preview and clearer feedback

A lightweight native editor (Qt 6 + Scintilla) with built-in Preview and Terminal.

### Changes since 0.6.1
- **Faster Preview.** The Preview page no longer waits on a network name lookup before it loads. Opening a large Markdown file with the Preview showing took 2.6–2.7 s from launch to rendered page in 0.6.1. In 0.6.2 it takes 1.4–1.5 s (three runs each, same file and window size).
- **Loading feedback.** A thin bar shows at the top of the Preview while it starts and while a large file renders. Quick refreshes while you type don't show it.
- **Render errors.** If a document can't be rendered, the Preview shows the error and that document's own text. It no longer keeps the previous document on screen. Edit mode and View only now behave the same.
- **OpenAPI.** Markdown styles no longer leak into the API page: the version badges, parameter tables and headings look as Swagger UI intends. The **Schemas** section is shown again.
- **Fixed:**
  - Math inside link text (for example `[$x$](#a)`) no longer makes the whole Markdown document fail.
  - In the Terminal, the mouse wheel scrolls full-screen programs such as vim and Pi instead of sending arrow keys. MDLite now ships the newer Windows console host (`conpty/`, MIT; license in `licenses/ConPTY-MIT.txt`).
  - Go to Symbol no longer freezes on files with very long lines.

### Requirements
- Windows 10 (1809 or later) or Windows 11, x64.
- Preview and Terminal use the Microsoft Edge **WebView2 Runtime**, which comes preinstalled on Windows 11.

### Install
- **Microsoft Store:** https://apps.microsoft.com/detail/9NGXBT327D13. It is signed by Microsoft, so there is no SmartScreen warning. The 0.6.2 update reaches the Store after certification.
- **Installer:** run `MDLite-0.6.2-windows-x64-setup.exe`. It updates an existing 0.5.x or 0.6.x install in place. The app is not code-signed yet, so Windows SmartScreen may ask you to confirm: choose "More info", then "Run anyway".
- **Portable:** unzip `MDLite-0.6.2-windows-x64.zip` anywhere and run `MDLite.exe`. The portable copy does not register "Open with". If you unzip over an older portable copy, delete the old `preview` and `terminal` folders first.

Settings, `keybindings.json` and hot-exit backups are stored in your user profile (AppData). They are kept when you uninstall or update.

### Validation and known limits
- **Automated tests:** built with Qt 6.8.3 / MSVC 2022 on Windows 11. All 54 automated tests passed, run one at a time. New tests cover:
  - Preview start time: it must be ready within 1.5 s (measured 0.38 s);
  - a failed render showing the current document's text;
  - Markdown styles kept out of the OpenAPI page, and the Schemas setting;
  - math in link text, the Terminal mouse wheel, and Go to Symbol on long lines.
- **Install tests:**
  - Deployment smoke tests passed for the package and for an installer update from 0.6.1. The update left exactly the package's files and registered the file types.
  - The silent uninstall removed every file and the file-type registration.
- **Memory:**
  - Editor-only memory is unchanged at about 15.6 MiB private working set (1600×1000 window).
  - With the Preview open on the same large Markdown file, the whole process tree (WebView2 included) uses about 137–140 MiB in both 0.6.1 and 0.6.2.
- **Known issues:**
  - Programs started from the Microsoft Store version of PowerShell run outside MDLite's process group.
  - "Open with" in the Microsoft Store version has not yet been checked on a Store install.
- **Not yet validated:** Windows 10, clean-machine installs, Linux/macOS (no Preview/Terminal host there yet), live screen-reader sessions.

Third-party notices are included in the package (`licenses/`, `terminal/THIRD_PARTY_NOTICES.md`).

### Source code
The complete source code of this version is attached as `MDLite-0.6.2-source.zip`. The *Source code (zip)* and *(tar.gz)* links that GitHub adds to every release contain only the public files of this repository (README, privacy statement, license, release notes).

Building it: follow `docs/BUILDING.md` in the archive. In this version a first build in a new build directory stops while copying the console host; create the folder `build/cmake/Release/conpty` and build again.
